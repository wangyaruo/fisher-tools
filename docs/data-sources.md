# 数据源说明

## 总览

| 数据 | 来源 | 授权 | 是否需要 Key |
| --- | --- | --- | --- |
| 气象（气温、气压、风、云、降水、湿度、能见度、紫外线） | Open-Meteo `/v1/forecast` | CC BY 4.0 | 否 |
| 海洋（浪高、浪周期、浪向、海表水温） | Open-Meteo `/v1/marine` | CC BY 4.0 | 否 |
| 月相、日月出没、solunar 时段 | `astronomy-engine` 本地计算 | MIT | 否 |
| 潮汐窗口 | 本地天文潮推算 | — | 否 |

`/health` 与 `/` 会返回 attribution 字符串，前端页脚与各页面「数据来源」区块
原样展示，满足 CC BY 4.0 的署名要求。

## Open-Meteo

请求参数固定带 `timezone={钓点时区}`，**让上游直接返回当地时间字符串**。
这是刻意的：如果拿 UTC 再自行换算，午夜边界与夏令时会成为持续的 bug 来源。
所有时刻在本项目中统一为「钓点当地墙上时间」。

逐小时要素（`HOURLY_FIELDS`）与上游字段名一一对应，不做重命名——
重命名会让代码与官方文档对不上，排查问题时多一层心智映射。

逐日要素额外取了 `sunrise` / `sunset`，用途之一是与本地 astronomy-engine
的计算结果做交叉验证（见下）。

### 缺失值的处理

上游返回的数组元素可能是 `null`，处理策略按要素重要性分两档：

- **核心要素**（`temperature_2m`、`surface_pressure`、`pressure_msl`、
  `wind_speed_10m`、`wind_direction_10m`、`cloud_cover`、`precipitation`）
  缺失时**直接抛错**，映射为 502。
  不能用 0 兜底：那会把「没有数据」变成「气压为 0」，直接污染评分结论。
- **次要要素**（体感温度、露点、湿度、阵风、降水概率、能见度、紫外线）
  允许兜底，取值口径在代码注释中写明。能见度与紫外线缺省为 0 表示「未知」，
  二者**均未参与评分**，因此不会影响结论。

### 海洋数据的降级

海洋数据用独立请求（`/v1/marine`）。内陆坐标上游会返回错误，
**这是预期情况而非故障**，因此失败时降级为空数组并置 `hasMarineData = false`，
由前端隐藏海洋面板并显式说明原因。

钓鱼指数中的「温度因子」在沿海点位用海表水温、在内陆点位用气温作为代理指标，
降级路径在页面上可见，不静默切换。

### 配额

Open-Meteo 免费层按日限量。项目内已用 `CACHE_TTL_SECONDS`（默认 600 秒）
的内存缓存与同键并发去重降低上游压力，`/health` 的 `inflightDeduped`
计数可直接观察去重效果。若要面向较大流量，应改用自建缓存或付费层。

## astronomy-engine

纯 TypeScript 实现，无原生依赖，不需要网络。提供：

| 计算 | 输出 | 备注 |
| --- | --- | --- |
| 月相 | `phase`（0–1）、`illuminatedFraction`、`age`、`distance`、`altitude` | 八分月相名称由 `phase` 判别，比农历日期更适合作为程序内部口径 |
| 日月出没 | 日出、日落、太阳正午、民用晨昏（−6°）、航海晨昏（−12°） | |
| 黄金时段 | 太阳高度 −4° 至 6° 的区间 | 光线入射角低、水体反差强，掠食性鱼种视觉优势最明显 |
| 月亮时刻 | 月出、月落、月中天、月下中天 | 极区或当日不发生时为 `null` |
| solunar 时段 | 主要时段（中天前后各 1 小时）、次要时段（月出月落前后各 45 分钟） | |

**solunar 是经验假说。** 该理论由 John Alden Knight 于 1926 年提出，
是钓鱼界流传最广的日月周期假说，但缺乏严格的对照实验支持。
因此 `method` 字段随结果一起下发，前端必须原样展示，不得包装成确定性结论。

## 潮汐：为什么只给窗口

**精度边界**：中国境内暂无稳定的免费站点级潮位接口。因此当前实现只做天文潮近似，
**不提供潮高与具体潮时**——`extremes` 与 `hourlyHeights` 恒为空数组，
而不是用一个模型凑出看似精确的数值。

实现方式：按当地正午采样月相，取朔望潮强度 `|cos(2π·相位)|`：

| 强度 | 判定 |
| --- | --- |
| ≥ 0.75 | 大潮窗口（朔望附近，潮差较大、潮流交换强） |
| ≤ 0.25 | 小潮窗口（方照附近，潮差较小、水体交换弱） |
| 其余 | 中潮窗口 |

连续同类型的日期会合并成一段窗口——朔望前后数天的潮差都明显偏大，
实际出钓需要的是一个可安排的日期区间，而不是单日。

**必须一并说明的两点局限**：

1. 这是朔望周期的基频分量，属简化近似。真实潮汐是多个分潮
   （M2、S2、K1、O1 等）的叠加。
2. **潮龄效应**：大潮实际出现时间通常比朔望滞后 1 至 2 天。
   此外潮汐还受海底地形、水深与气象（气压、风）影响。

海钓请以当地海洋预报机构的潮汐表为准。这段声明通过 `disclaimer` 字段
随响应下发，前端在潮汐面板中原样展示。

## 交叉验证记录

按要求，涉及方向与数值的结论需要交叉验证，以下是已完成的两项：

| 项目 | 方法 | 结果 |
| --- | --- | --- |
| 日出日落 | 本地 astronomy-engine 计算值 vs Open-Meteo 逐日 `sunrise` / `sunset` 字段 | 2026-09-10 深圳：两地来源均为 06:08 / 18:32，**完全一致** |
| 潮汐窗口 | 窗口中心日期 vs 月龄 | 窗口 09-08 至 09-13 以 09-11 新月为中心，与月龄 28.43 天自洽 |

`astronomy-engine` 的本地计算与上游气象服务商（数据来源为多家国家气象机构）
在日出日落上完全一致，说明两套独立实现在该点上无系统性偏差。

## 缺失数据与评分的关系

钓鱼指数共 10 个因子。任一因子所需数据缺失时，该因子被标记为 `degraded`，
并按**剩余因子的权重归一化**后计分，而不是用默认值填充出一个看似完整的分数。

前端在因子图上把 `degraded` 因子用中性色标出，`caveats` 字段列出降级说明，
因此用户可以区分「这个因子确实中性」与「这个因子没有数据」。

## 免责声明汇总

- 钓鱼指数是**启发式模型**，基于公开数据的相对提示，不构成出钓保证。
- 潮汐为**天文潮近似**，不含站点潮高与具体潮时。
- solunar 时段属**经验假说**，不同水域表现差异较大，建议结合本地渔获记录校验。
- 知识库**不提供法规条文**的时间与范围，各地规定差异大且会调整，
  必须到官方渠道确认当日有效版本。
